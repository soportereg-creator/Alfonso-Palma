1) PARA QUÉ SIRVE ESTE PROYECTO
--------------------------------------------------------------------------------

Es un portal interno de CONSULTAS de facturación electrónica de INFILE
para tres países: Panamá, República Dominicana y Costa Rica.

NO es un emisor de facturas.
NO es un ERP.
NO es un dashboard de clientes finales.

SÍ es una herramienta para:
  - Probar APIs de INFILE / PAC / Hacienda / DGII desde el navegador.
  - Ver la respuesta JSON (o descargar PDF) sin Postman.
  - Centralizar en una sola app los servicios multi-país.

Usuario típico: equipo INFILE (soporte, QA, implementación, diseño).
El dueño de este workspace es Alfonso (Designer). Prefiere iterar en código.

4) CÓMO ESTÁ ARMADO (ARQUITECTURA)
--------------------------------------------------------------------------------

Flujo:

  [Página país, 'use client']
        │  fetch('/api/pais/servicio')
        ▼
  [Route Handler Next.js: app/api/.../route.ts]
        │  fetch() server-side hacia API real
        ▼
  [INFILE PAC / DGII / Hacienda CR / gateway staging]
        │
        ▼
  JSON o PDF de vuelta al ServiceCard

Por qué hay proxies:
  Evitar CORS, reenviar headers/tokens, y (en RD) poner la API key en servidor.

Componente clave:
  components/ServiceCard.tsx
    - Campos dinámicos
    - GET o POST
    - apiPath interno
    - extraHeaders (Panamá)
    - authToken Bearer (Costa Rica)
    - isBinary para PDF
    - Muestra status, tiempo, JSON copiable

El header/nav/footer está DUPLICADO en:
  app/page.tsx
  app/panama/page.tsx
  app/dominicana/page.tsx
  app/costarica/page.tsx
Si extraes layout compartido, hazlo con cuidado y verifica las 4 pantallas.

6) RUTAS API (PROXIES) Y DESTINOS
--------------------------------------------------------------------------------

PANAMÁ  (query ?env=test|prod, headers usuario-api, llave-api, llave-firma)
  POST /api/panama/ruc
       → infile-pac-unificado.herokuapp.com
         /api/v1/consultas/unificado/{env}/json/ruc_dv

  POST /api/panama/anulacion
       → .../api/v1/eventos/unificado/{env}/json/anulacion
         Body: { cufe, motivo_anulacion }
         CUIDADO: esto dispara un evento de negocio, no es solo lectura.

  POST /api/panama/cufe
       → .../api/v1/consultas/unificado/{env}/json/factura

  PDF Panamá NO pasa por /api: el cliente arma la URL del certificador:
    test: https://certificador-test.infilepac.com/pac/v1/dev/descargas/pdf/{cufe}
    prod: https://certificador.infilepac.com/pac/v1/dev/descargas/pdf/{cufe}

REPÚBLICA DOMINICANA
  GET /api/dominicana/rnc?rnc=
       → api-dgii.dominicantechnology.com/api/v1/rnc/{rnc}

  GET /api/dominicana/mantenimiento
       → statusecf.dgii.gov.do .../ObtenerVentanasMantenimiento
         Header authorization = DGII_API_KEY

  GET /api/dominicana/estatus
       → .../ObtenerEstatus

  GET /api/dominicana/ambiente?ambiente=1
       → .../VerificarEstado?ambiente=

COSTA RICA
  GET /api/costarica/cedula?identificacion=
       → api.hacienda.go.cr/fe/ae  (público, sin token INFILE)

  POST /api/costarica/login
       Body: { prefijo, llave }
       → api-gateway-staging.infile.com/api/cr/v1/login
         Extrae token (token | access_token | Bearer | bearer)

  GET /api/costarica/documento?uuid=   + Authorization Bearer
       → api-gateway-staging.infile.com/api/cr/v1/consultar/{uuid}

  GET /api/costarica/pdf?uuid=         + Authorization Bearer
       → report-engine-regional-staging.infile.com
         /api/cr/v1/documento/{uuid}?tipo_documento=pdf
         Respuesta: application/pdf

Costa Rica está cableada a STAGING. Panamá sí tiene Test/Prod.

9) SECRETOS Y RIESGOS (LA IA DEBE CUIDAR ESTO)
--------------------------------------------------------------------------------

  - Las rutas /api/* NO tienen login propio. Quien tenga la URL del portal
    puede usar los proxies.
  - Panamá: credenciales PAC van por defecto en el ESTADO del cliente
    (app/panama/page.tsx). No las imprimas ni las copies a docs nuevos.
  - RD: DGII_API_KEY en .env.local, con fallback hardcodeado en
    app/api/dominicana/{estatus,ambiente,mantenimiento}/route.ts
    Lo correcto es solo process.env.DGII_API_KEY, sin fallback en código.
  - No subas .env.local a git público.
  - Evento de anulación en Panamá es destructivo a nivel de comprobante.

Si te piden “hacer el proyecto más seguro”, prioriza:
  quitar keys del cliente y del código, usar env vars, no abrir prod
  sin confirmación, y no loguear tokens.
